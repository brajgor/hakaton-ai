# Нормативный rule engine без AI/RAG

## Статус документа

Это описание **реализованного hackathon MVP** и его чётких границ. Сервис
выполняет priekšpārbaude по открытым данным; он не выдаёт разрешение и не
интерпретирует нормативный текст во время запроса. Во всех ответах API остаётся
дисклеймер: «Šī ir priekšpārbaude, nevis galīgā atļauja. Galīgo lēmumu pieņem
kompetentā iestāde.»

React-интерфейс намеренно не менялся. Он продолжает отправлять `intentId` и
`addressId`; API также принимает необязательные параметры проекта для аудита.

## Что работает сейчас

1. API находит нормализованный адрес и проверяет геометрию точки в PostGIS.
2. Из слоёв собираются `DataFinding`: культурное наследие, ĪADT, функциональная
   зона, а для полного Рижского импорта также красная линия, охранные зоны
   наследия, культурно-исторические территории, охраняемая застройка,
   прибрежные зоны, микрорезерваты и риск затопления.
3. `PrecheckRuleEngine` выбирает только правила, которые действуют на дату
   проверки, подходят муниципалитету, действию и найденному пространственному
   флагу.
4. Результат содержит пользовательский уровень (`green`, `yellow`, `red`),
   формальный статус, коды причин, следующие шаги, предупреждения о покрытии и
   применённые версии правил с официальными ссылками и SHA-256 снимков.
5. В `precheck_runs` сохраняются входные параметры, дата проверки, находки,
   результат, версии правил и цитаты, так что конкретный ответ можно
   воспроизвести.

### Статусы

| UI | Rule engine | Смысл |
| --- | --- | --- |
| `green` | `no_known_blocker` | В загруженных открытых данных не найдено ограничение для выбранного действия. Это не разрешение. |
| `yellow` | `conditions_apply` | Найдено условие охраняемой природной территории или зоны риска; нужны требования компетентного органа. |
| `yellow` | `manual_review_required` | Найдено наследие, охранная территория Риги или красная линия; необходима ручная проверка. |
| `red` | `insufficient_data` | Адрес отсутствует/неоднозначен, поэтому пространственную проверку нельзя завершить. |

## Реестр и аудит

Исходник MVP-правил находится в `src/VaiDrikstu.Domain/RuleCatalog.cs`. Это
осознанный контролируемый источник истины, а не LLM и не свободный разбор
законов. При запуске API он идемпотентно проецируется в PostGIS:

- `legal_sources` и `legal_source_versions` — официальная ссылка и SHA-256
  конкретного локального снимка;
- `rules` — `rule_id`, версия, период действия, юрисдикция;
- `rule_conditions` — действие и пространственный флаг;
- `rule_effects` — статус, код причины и подготовленные следующие шаги;
- `rule_citations` — связь правила с пунктом нормы и версией снимка;
- `spatial_flags` — нормализованные геометрические флаги;
- `precheck_runs` — аудит конкретного ответа.

В MVP действуют следующие правила:

| Rule ID | Условие | Результат |
| --- | --- | --- |
| `HERITAGE_REVIEW` | Наследие рядом или пересекается с адресом | `manual_review_required`, проверка NKMP/самоуправления. |
| `RIGA_HERITAGE_ZONE_REVIEW` | Рижская охранная или культурно-историческая территория | `manual_review_required`. |
| `PROTECTED_NATURE_CONDITIONS` | ĪADT, микрорезерват или прибрежная зона для солнечных панелей, вывески, террасы или малой постройки | `conditions_apply`, проверка DAP. |
| `RIGA_RED_LINE_REVIEW` | Рижская красная линия для солнечных панелей, террасы или малой постройки | `manual_review_required`. |
| `RIGA_FLOOD_RISK_CONDITIONS` | Рижская зона риска затопления для солнечных панелей, террасы или малой постройки | `conditions_apply`. |

Правила имеют `effectiveFrom`, `effectiveTo`, юрисдикцию и версии. Новая
нормативная редакция должна добавлять новую версию, а не переписывать историю.

## Проанализированные источники

Локальная папка `new_data/` не попадает в Git и Docker build context. Её
`external/manifest.json` фиксирует URL и SHA-256 файлов, загруженных 2026-10-10.
В `legal_source_versions` регистрируются следующие официальные снимки:

| Источник | Роль в системе сейчас |
| --- | --- |
| Būvniecības likums | Контекст будущей классификации процедуры; не даёт автоматическое разрешение без параметров проекта. |
| Ēku būvnoteikumi, MK Nr. 529 | Будущая классификация работ со зданием и документов. |
| Vispārīgie būvnoteikumi, MK Nr. 500 | Будущая классификация группы сооружения и этапов процесса. |
| Rīgas teritorijas izmantošanas un apbūves noteikumi | Цитируется для Рижских правил; функциональная зона импортируется, но ещё не даёт автоматического verdict. |
| Aizsargjoslu likums | Цитируется в правиле красной линии. |
| Par kultūras pieminekļu aizsardzību | Цитируется в правилах наследия. |
| ĪADT vispārējie aizsardzības un izmantošanas noteikumi | Цитируется в правиле природы. |
| Rīgas RTP 2030 ArcGIS-слои и GeoPackage красных линий | Импортируются в `spatial_flags` и являются фактами для Рижских правил. |

Импортёр использует только векторные GeoJSON и GeoPackage с геометрией. TAPIS
и плёновые WMS/XML в текущей поставке сохранены в `source_catalog` как
`reference-only`: без полноценной, проверенной векторной геометрии они не
участвуют в автоматическом пересечении.

## Входные параметры

`POST /api/precheck` обратно совместим с текущим UI:

```json
{
  "intentId": "terrace",
  "addressId": "addr-heritage-riga",
  "project": {
    "placement": "yard",
    "areaSquareMeters": 12,
    "heightMeters": 3,
    "floorCount": 1,
    "changesFacade": false
  },
  "checkedOn": "2026-10-10"
}
```

`project` и `checkedOn` уже сохраняются для воспроизводимости. Они пока не
меняют результат: ни размеры, ни высота не должны становиться юридическим
правилом до ручного переноса и проверки нормы специалистом.

## Что ещё нельзя обещать

- Не нормализованы все lokālplānojumi и detālplānojumi.
- Не загружены как проверяемые векторные слои все инженерные охранные зоны.
- Функциональная зона Риги видна в аудите, но параметры допустимой застройки
  ещё не превращены в формальные правила.
- Не проверяются точная геометрия проектируемого объекта, границы участка,
  согласия собственников и закрытые реестры.
- Открытые данные не заменяют BIS, строительную управу, NKMP или DAP.

Поэтому `green` означает только «в доступном наборе данных не найден известный
блокирующий сигнал для выбранного действия», а не «строительство разрешено».

## Как обновлять правила

1. Скачать новую официальную редакцию или геослой, сохранить URL, дату и
   SHA-256 в локальном manifest.
2. Сравнить изменения и передать их специалисту по соответствующей норме.
3. Добавить новую версию правила и точную цитату в `RuleCatalog`; не изменять
   старую версию задним числом.
4. Добавить эталонные сценарии в `PrecheckRuleEngineTests`, пересобрать API и
   проверить `precheck_runs` на сохранённые версии и цитаты.

Такой процесс автоматизирует загрузку, хеширование, импорт геометрии и тесты,
но сохраняет юридическую интерпретацию как контролируемое человеческое решение.
